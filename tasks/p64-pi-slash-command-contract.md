# P64 — Pi built-in slash-command contract

Status: registry implemented; actor-owned command execution remains open
(2026-08-08)

## Source contract

Pi defines `BUILTIN_SLASH_COMMANDS` in
`/Users/admin/Code/agents/pi/packages/coding-agent/src/core/slash-commands.ts`.
The current source registry contains 22 ordered commands. Each has a stable
name, description, and optional argument hint (`model`, `login`).

## Runie implementation

`runie-core::commands::PI_BUILTIN_SLASH_COMMANDS` is generated by a small
declarative macro. `matching_pi_builtin_slash_commands` is a pure,
case-insensitive name/description filter and owns no UI or actor state. The
registry is therefore reusable by an actor, RPC boundary, YAML oracle, or TUI
projection without duplicating command strings.

Focused tests assert source order, count, argument hints, and pure filtering.
`crates/runie-core/tests/fixtures/pi-slash-commands.yaml` is also loaded at
test runtime and compares the complete registry, keeping the scenario data
editable without recompiling the test harness.

## Remaining boundary

The registry deliberately does not execute commands. Pi execution has distinct
effects (session mutation, provider/auth changes, compaction, navigation, and
process termination). Each supported Runie command must be represented as a
typed event/mailbox request owned by the relevant actor, with an async result
and a YAML event-sequence/state assertion before it is exposed in the TUI.
Unsupported effects must return an explicit typed capability result rather than
being treated as successful no-ops.

# Grok TUI behavior inventory and Pi-core mapping

Status: active (2026-08-07)

## Current source audit (2026-08-07)

`scripts/source-inventory.sh` currently reports 48 Pi agent files, 174 Pi AI
files, 496 Grok pager files, and 68 Grok pager-render files. The inventory is
therefore synchronized with the checked-out references. This does not close
the behavioral acceptance criteria below: the remaining evidence gaps are
full-cell cast attributes/telemetry and reducer-owned opaque tool-row identity.

This is the source-backed behavior inventory for the Grok pager. The target is
the Grok presentation of events that Runie can receive from Pi core; Grok-only
ACP, sessions, providers, MCP, voice, plugins, billing, dashboards, and
filesystem integrations are catalogued as out of scope unless a matching
`runie-core` event is added deliberately.

## Feed lifecycle: when entries appear

| Feed item | Grok source contract | Pi-core event mapping | Runie evidence/plan |
|---|---|---|---|
| User entry | `scrollback/blocks/user.rs`; inserted at prompt submission, retains timestamp and follow-latest anchor | `MessageStart`/`MessageEnd(User)` | `visual-hey.yaml`, four-size matrix; verify exact vpad and anchor |
| Assistant entry | `scrollback/blocks/markdown_content.rs`, `entry.rs`; shell appears on assistant start, deltas extend the same content block, end settles it | `MessageStart(Assistant)`, `MessageUpdate`, `MessageEnd` | YAML text sections and full-screen snapshots |
| Thinking entry | `blocks/thinking.rs`; starts as live `Thinking…`, receives deltas, settles to elapsed summary, folds independently | assistant thinking start/delta/end | `visual-thinking-sections.yaml`; timing/attribute cast parity remains open |
| Tool header | `blocks/tool/*.rs`; created on execution start with family-specific header and running state | `ToolExecutionStart` | typed `ToolBlock` projection and tool fixtures |
| Tool output | family block stores partial output; update events append/replace content without creating a second header | `ToolExecutionUpdate` | `visual-tool-update.yaml`; row ownership/completion placement open |
| Tool completion | family derives count/status from stored result; header and body rendering depend on display mode | `ToolExecutionEnd` plus result message | `visual-activity-mixed.yaml`; source-aligned header update under validation |
| Tool result message | transcript result blocks are inserted after execution settlement | `MessageStart/End(ToolResult)` | replay state assertions |
| Activity group | `state/verb_group.rs`, `state/groups.rs`; consecutive compatible tools share a summary; message boundaries break groups | lifecycle sequence and assistant/user boundaries | dense-group YAML and viewport reveal oracle |
| Background/workflow | `blocks/bg_task.rs`, `subagent.rs`, `workflow.rs`; visible immediately on start, updates mutate the same card, end settles status | background/workflow lifecycle events | lifecycle YAML; specialized full rendering open |
| Waiting/status | `views/turn_status.rs`, `views/status_bar.rs`; appears after event boundary while next provider phase is pending | `Waiting`, turn/agent lifecycle | waiting-reason YAML and visual captures |

Important ordering invariant: feed insertion is event-driven, not timer-driven.
An item becomes visible after its owning reducer acknowledges the start/update
event. Animation ticks may repaint an existing live item but must not create
feed content.

Lifecycle mutation invariant: update, completion, and error intents resolve the
semantic tool-header row, never an arbitrary output line sharing the same call
ID. This preserves Grok's separate header/status and body/output surfaces and
is now enforced by the Runie scrollback reducer.

## Animation and timing contract

| Effect | Source | Behavior to reproduce | Runie status |
|---|---|---|---|
| Thinking/live spinner | `blocks/thinking.rs`, `theme/*.rs` | deterministic frame selected from an owned tick; accent glyph/color changes while active, settles to static elapsed summary | actor-owned frame state; exact cast cadence open |
| Running tool bullet | `blocks/tool/*.rs`, `render/draw.rs` | live accent bullet/indicator; completion switches to static success/error treatment | YAML lifecycle coverage; color attributes open |
| Status spinner | `views/turn_status.rs`, `views/status_bar.rs` | frame progression only while status requests animation; idle/terminal states stop demand | actor-owned demand and deterministic frames |
| Theme accent wave | `theme/tokyonight.rs`, `theme/groknight.rs`, `theme/grokday.rs` | frame/tick brightness is derived from theme tokens, never hard-coded in widgets | Opaline tokens present; full truecolor proof open |
| Progress/title keepalive | `notifications/mod.rs`, `notifications/progress.rs` | busy progress is deduplicated and refreshed no more often than `PROGRESS_KEEPALIVE = 5s` | out of scope unless exposed by core event |
| System appearance watcher | `theme/system_appearance.rs` | auto mode polls OS/OSC11; source constants include 5s and 50ms intervals | out of scope for Pi-only TUI; theme event remains in scope |

Animation tests must control frame/tick inputs explicitly. They must not use
`sleep()` or infer a frame from wall-clock scheduling.

**Declarative tick replay (2026-08-07):** YAML now accepts
`animation_ticks: N`. Each declared tick is reduced through both the
actor-owned status and feed projections, and state assertions can pin
`animation_frame` and `elapsed_ticks`. The `visual-animation-events.yaml`
fixture keeps the status active while ticking, then checks the complete
rendered screen. This makes animation progression editable without
recompilation and confirms that ticks repaint existing rows rather than
creating feed entries. Terminal states intentionally reset/ignore animation
advances, matching the actor demand predicate.

## Input box behavior

Primary sources: `views/prompt_widget/mod.rs`, `input/line_editor.rs`,
`views/prompt_widget/tests.rs`, `views/completion_dropdown.rs`,
`views/prompt_suggestion.rs`, and `app/agent_view/prompt.rs`.

- Empty prompt renders placeholder/model chrome and a cursor; typed text renders
  the editor with Unicode display-width-aware cursor placement.
- Enter submits a non-empty prompt; Shift/Alt-Enter inserts a newline according
  to mode. Multiline height changes layout and preserves one gutter per logical
  line.
- Up/Down on an empty prompt browse history; while editing they move the cursor
  or navigate completion context. Escape clears/exits transient prompt modes.
- `@` activates file search; Tab accepts a candidate; Ctrl-L opens the selected
  file in the bounded line viewer. The dropdown and viewer are overlays, not
  feed entries.
- Prompt mode cycles (normal/alternate/plan) alter border, caption, submit
  semantics, and available actions. Mode is state, not a color side effect.
- Submission transfers the follow-latest anchor to the newest user entry; new
  incoming content follows the tail only while the user has not explicitly
  scrolled away.

Pi mapping: prompt text becomes a `UserMessage`; mode and editor behavior are
TUI-local. No prompt keystroke may mutate core state outside an intent/event.

## Command palette and dialogs

Sources: `views/picker.rs`, `views/modal.rs`, `views/modal_window.rs`,
`views/overlay_list.rs`, `views/shortcuts_help.rs`, `views/slash_dropdown.rs`,
`app/agent_view/modals.rs`, `app/dispatch/router.rs`, and `actions/defaults.rs`.

- Palette activation opens a modal overlay with title, filter input, selected
  row, keyboard hints, and a scrollable result list.
- Filtering is incremental and selection is clamped/wrapped as the result set
  changes. Enter dispatches a typed action; Escape restores the underlying view
  without changing feed/core state.
- Slash completion is a separate prompt-attached dropdown; it shares matching
  logic but not modal ownership or layout.
- Shortcut help is a read-only modal; command palette actions are executable
  intents. Modal chrome uses theme tokens and terminal-width-aware padding.
- Settings, permissions, plan approval, file viewer, question, and session
  pickers reuse modal primitives but are separate state machines.

The command-palette configuration uses an input-focused picker and
`esc_clears_query: true`: the first Escape clears the query and resets
selection while retaining the modal; the next Escape closes it. Runie now
models this as `UiMsg::CommandPaletteEscape` in the UI actor rather than a
terminal-loop special case.

Pi mapping: only actions backed by Pi-core features are Runie requirements
(model/effort, queue/steering, plan if promoted, transcript navigation, and
core tool/display controls). Grok account/session/dashboard commands remain
out of scope.

## Hotkeys and interaction states

Sources: `actions/defaults.rs`, `input/key.rs`, `app/agent_view/interactions.rs`,
`scrollback/state/nav.rs`, `scrollback/state/selection.rs`, and
`views/shortcuts_bar.rs`.

| Key/action family | State transition | Pi-core mapping |
|---|---|---|
| Enter / Shift-Enter | submit vs insert newline | user prompt event |
| Up/Down | history, cursor, or semantic feed selection by mode | no core mutation unless submit |
| Ctrl-C | clear prompt first; abort active run; quit only when idle and empty | abort token/event |
| Ctrl-D/Ctrl-Q | quit under idle/empty guard | process control, out of core |
| Ctrl-P / `?` | open command palette/help | TUI action |
| Ctrl-X | open shortcuts/help surface | TUI action |
| Ctrl-L | file-search line viewer | TUI file overlay |
| `e` | toggle selected feed block fold when prompt is empty | display-mode event |
| `j`/`k`, arrows | select semantic entries; reveal hidden dense group | display selection event |
| Ctrl-J/Ctrl-K | scroll viewport | display scroll intent |
| Tab / Shift-Tab | accept completion or cycle input mode | prompt-local state |
| Escape | clear text/close transient overlay/no-op by state | TUI state |

Key handling is mode-dependent and must be tested as event sequences, not as
isolated key-to-function mappings.

## Tags, statuses, and metrics

Sources: `views/status_bar.rs`, `views/turn_status.rs`, `views/context_bar.rs`,
`views/credit_bar.rs`, `app/status_blocks.rs`, `scrollback/blocks/*.rs`, and
`headless/reducer/messages/usage.rs`.

- Turn states include idle/ready, thinking, streaming, executing tools,
  waiting, completed, aborted, and error. Each state has distinct label,
  spinner demand, accent role, and footer hints.
- Tool tags include family (execute/read/edit/list/search/web/background),
  display mode (collapsed/truncated/expanded), running/finished/error, and
  selection/reveal state.
- Usage surfaces may show model, token counts, cache/cost fields, elapsed
  time, stop reason, and context budget. A metric is visible only when its
  owning state has a value; zero/unknown values have distinct source behavior.
- Context/status bars can show queued steering/follow-up counts, active tool
  count, session/model labels, and plan/permission state. Pi-limited Runie
  maps only values available from core snapshots/events.
- Error rows preserve provider/tool/abort classification and are not silently
  converted to generic failure text.

## Theme, glyph, and layout details

Renderer sources: `xai-grok-pager-render/theme/*.rs`, `render/color.rs`,
`render/safe_buf.rs`, `render/wrapping.rs`, `render/terminal_output.rs`,
`glyphs.rs`, `scrollback/layout.rs`, and `views/agent_view/render.rs`.

- GrokNight and GrokDay define semantic tokens for base/background, primary,
  muted, accent, success, warning, error, prompt border/focus, selection,
  path, tool output, and model/usage roles.
- Terminal-native/reset colors are a deliberate third capability path; RGB
  tokens must be quantized only when terminal capability requires it.
- Layout derives prompt, footer, status, feed, and overlay heights from the
  terminal geometry. Compact mode is height-sensitive; width controls wrapping,
  truncation, modal padding, and path shortening.
- Safe-buffer writes preserve cell width, background, modifiers, hyperlinks,
  and empty cells. A parity comparison must include all of those attributes.
- Tool headers use bold only for the action verb/name where the source block
  defines a split span; output uses family-specific indentation and optional
  panel background.

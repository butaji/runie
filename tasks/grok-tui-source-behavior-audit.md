Status: active (2026-08-06)

Scope: `Runie = Pi Core with Grok TUI`, where the TUI surface is as rich as
Grok but only Pi-core capabilities are implemented. This is a source audit,
not a claim that Grok-only ACP, account, session, dashboard, voice, plugin,
or billing features belong in Runie.

## 1. Feed lifecycle: when each item appears

### Event-to-row contract

| Event boundary | Grok projection | Appearance/update rule | Pi/Runie plan |
|---|---|---|---|
| user prompt accepted | `scrollback/blocks/user.rs`, prompt path in `app/agent_view/prompt.rs` | Insert one user block at submit. The newest prompt becomes the follow-latest anchor; it is not a timer-generated row. | `UserMessage` event → actor-owned user row; assert anchor and one-row offset in YAML. |
| assistant/reasoning starts | `scrollback/blocks/entry.rs`, `blocks/thinking.rs` | Create a live block at the start event. Subsequent deltas mutate that block; they must not create one row per delta. | `MessageStart`/`MessageUpdate`/`MessageEnd` replay. |
| assistant text starts | `blocks/markdown_content.rs`, `blocks/entry.rs` | First text delta materializes content; later deltas extend the same sectional content and remeasure wrapping. | Section identity and reflow state in snapshot. |
| tool starts | `scrollback/blocks/tool/mod.rs` and specialized `tool/*.rs` | Insert a family-specific running header immediately when execution starts. The body may still be empty. | `ToolExecutionStart` → typed block identity. |
| tool updates | specialized tool block | Mutate the existing call-owned body/header state. Partial output is rendered while running. | `ToolExecutionUpdate` targets call ID; no arbitrary-line mutation. |
| tool ends | specialized tool block + `state/verb_group.rs` | Settle the same header/status row, derive counts/summary, and preserve body output. Error/cancel is a distinct terminal style. | `ToolExecutionEnd` and result event; assert row identity and terminal status. |
| consecutive tools | `scrollback/state/verb_group.rs`, `state/groups.rs` | Compatible neighboring calls may collapse into one activity group. User/assistant boundaries and incompatible families break grouping. | Group reducer fixture with member IDs and reveal/collapse events. |
| background/subagent/workflow starts | `blocks/bg_task.rs`, `blocks/subagent.rs`, `blocks/workflow.rs` | Insert a visible live card on start; phase/output events update it in place; completion changes status and elapsed data. | Pi-mappable only when a corresponding core event exists. |
| waiting | `views/turn_status.rs` | Status line appears after the event boundary that says the next phase is pending; repainting does not create feed content. | Typed `WaitingReason` state and status fixture. |

The invariant to preserve is: event reducers create or mutate semantic rows;
animation ticks only repaint existing live rows. The reducer must keep header,
body, result, group membership, and selection identity separate. This is the
source reason the “sent prompt appears at the wrong top position” bug cannot be
fixed safely by adding a render offset alone.

### Specialized item details

- Web search (`scrollback/blocks/tool/web_search.rs`) renders query, site
  count, deduplicated source domains, expanded result content, truncation, and
  a terminal success/error accent. A source summary is data, not decoration.
- Memory search (`tool/memory_search.rs`) parses result number, score, source,
  file path, line range, and fenced snippet. These fields must be optional and
  absent when the event does not provide them.
- Workflow (`blocks/workflow.rs`) has `Running`, `Done`, `Failed`, `Cancelled`,
  and `Paused` statuses, elapsed values, phase trail, current phase, and
  active-agent count. It is a card state machine, not generic tool text.
- Entry layout (`scrollback/entry.rs`, `scrollback/scrollback_pane.rs`) measures
  wrapped rows before painting. Sticky prompt headers can be pushed/pinned as
  scroll changes; timestamps overlay the first content row and do not alter
  message text.

## 2. Animation, colors, styling, and timing

### Clock ownership

Source: `app/event_loop.rs`, around the initial animation setup and the
`animation_tick` select arm.

1. `initial_config.animation.tick_interval()` supplies the animation interval.
2. `animation_tick_at` is `None` while no live animation/reconciliation needs
   a tick; `schedule_tick` arms it only when `app.needs_animation()` or an
   expiring action requires work.
3. The animation arm calls `app.tick()`, requests a repaint only when state
   changes, then reschedules while demand remains.
4. Draw throttling (`min_draw_interval`) and the dedicated scroll clock are
   separate. Stream redraws and wheel/trackpad motion must not be confused with
   animation cadence.
5. Grok source comments describe the normal render tick as approximately 30
   fps. The actual interval is configuration-driven, so Runie tests must feed
   explicit frame/tick events instead of sleeping or assuming wall-clock time.

### Exact glyph families

Source: `xai-grok-pager-render/src/glyphs.rs`.

| Use | Normal frames | Legacy fallback | Contract |
|---|---|---|---|
| monitor/status pulse | `○ ◎ ◉ ◎` | `· ○ • ○` | every frame is one terminal column |
| turn spinner | `⠋ ⠙ ⠹ ⠸ ⠼ ⠴ ⠦ ⠧` | `| / - \\` | fixed width prevents label movement |
| task/subagent dot | `⋅ : ⸬ ⁙ ⋅ : ⸬ ⁙` | `. : ·` | quiet one-column cycle |
| timeline/diamonds | `◆`, `◇`, `◈` | CP437-safe alternatives | semantic role is retained by color |

The TokyoNight renderer (`theme/tokyonight.rs`) exposes deterministic
`wave_brightness(tick, row, wave_rows, speed)` and
`pulse_brightness(tick, speed)`, both using `sin²` and returning `[0, 1]`.
The pulse documentation models a 30-fps frame clock; with `speed = 0.08` the
bright/dim cycle is about 1.3 seconds. These functions are pure and are ideal
for golden frame tests.

Animation parity requires recording: tick number, selected frame, glyph width,
foreground token, background token, modifiers, and coordinates. A color-only
or text-only dump is insufficient.

### Theme and cell styling

Theme definitions under `xai-grok-pager-render/src/theme` provide semantic
roles for base background, primary/muted/dim text, user accent, success,
warning, error, prompt border/focus, selection, path, tool output, and
model/usage. Widgets consume tokens; they do not own RGB literals.

The safe-buffer/terminal output path preserves empty cells, background, width,
modifiers, resets, and hyperlinks. Terminal capability probing may quantize
RGB only at the terminal boundary. Runie’s parity oracle must therefore compare
full cells and record the capability profile used for the capture.

## 3. Input box behavior

Primary sources: `app/agent_view/prompt.rs`, `app/agent_view/input.rs`,
`views/prompt_widget/mod.rs`, `input/line_editor.rs`,
`views/completion_dropdown.rs`, and `views/prompt_suggestion.rs`.

| State/gesture | Grok behavior | Required event fixture |
|---|---|---|
| empty prompt | placeholder/model chrome and cursor; prompt remains an input surface | `focus → render` |
| text insertion | Unicode display-width cursor and wrapped logical lines | chars including wide/combining text |
| bare Enter | submit non-empty prompt | `insert → Enter → UserMessage` |
| Shift/Alt-Enter | insert newline where multiline policy allows; prompt height remeasures | modifier-key sequence |
| Up/Down | empty editor browses combined history; non-empty editor navigates cursor/completion context | history vs editing branches |
| `@` | opens file-search dropdown; Tab/Enter accept; Esc dismisses; Ctrl-L opens bounded viewer | overlay state sequence |
| slash input | prompt-attached command dropdown intercepts arrows, Tab, Enter, and Esc before global actions | slash completion sequence |
| mode cycle | normal/alternate/plan changes state, caption, border, and action availability | mode event + screen assertion |
| submit while live | queue/steering policy decides immediate send versus queued follow-up; status line advertises the action | queue and interjection sequence |
| Ctrl-C/Esc | behavior depends on prompt text, active run, and transient overlay; it is not one global command | three-state matrix |

The important ordering rule is in `app/agent_view/prompt.rs`: visible file and
slash dropdowns receive their navigation/accept/dismiss keys before the action
registry, otherwise Tab would scroll and Enter would submit prematurely.

## 4. Command palette and dialogs

Sources: `views/picker.rs`, `views/modal.rs`, `views/modal_window.rs`,
`views/overlay_list.rs`, `views/shortcuts_help.rs`,
`app/agent_view/modals.rs`, `app/dispatch/router.rs`, and
`actions/defaults.rs`.

The palette is an input-focused modal overlay: frame/title, query editor,
filtered rows, selected row, keyboard hint/footer, and scrollable result area.
Filtering is incremental; selection is clamped to the filtered list. Enter
dispatches a typed action. Escape first applies the palette’s query-clear
policy where configured (`esc_clears_query`), then closes the modal. Closing
restores the underlying feed without changing Pi-core state. Slash completion
is a separate prompt-owned dropdown even though it shares matching concepts.

The picker primitives support floating and full-screen modes, centered popup
frames, dimmed background, rounded/bordered chrome, terminal-width-aware
padding, and theme-token styling. Runie should model overlay ownership in the
UI actor and keep command execution as an explicit intent/event.

## 5. Hotkeys and state-dependent routing

The authoritative registry is `actions/defaults.rs`; dispatch and precedence
are implemented in `app/agent_view/input.rs`, `app/agent_view/prompt.rs`, and
`app/dispatch/router.rs`. The same key can mean different things by focus and
state. The Pi-limited Runie inventory is:

| Family | Examples | Expected owner |
|---|---|---|
| prompt | Enter, Shift/Alt-Enter, Tab, arrows, Esc, Ctrl-C, Ctrl-M | prompt/UI actor |
| run control | send now, queue, interject, cancel/abort | core event boundary |
| feed navigation | arrows, j/k, page up/down, top/bottom, fold/expand | scrollback actor |
| overlays | command palette, shortcuts, model/settings/file viewer | UI actor + typed intent |
| display | raw markdown, thinking fold, selection, copy/open block | renderer/UI actor |
| process-only | quit and terminal capability controls | application boundary |

Every hotkey fixture must specify focus, prompt text, live status, overlay
state, and resulting state snapshot. Isolated key maps cannot prove parity.

## 6. Tags, statuses, and extra metrics

Sources: `views/turn_status.rs`, `views/status_bar.rs`, `views/context_bar.rs`,
`headless/reducer/messages/usage.rs`, and `scrollback/blocks/*.rs`.

Visible state categories include idle/ready, starting, thinking, streaming,
tool-running, waiting by reason, completed, aborted, and error. Tool rows add
family, running/terminal result, collapsed/truncated/expanded display mode,
selection, and grouping/reveal state. Workflow rows add phase trail and agent
count. Search rows add site/result counts and source domains.

Metrics are conditional, not unconditional labels: elapsed turn/phase time,
output-token count, context used/total, model, cache-read/cache-write,
cost, API duration, stop reason, queued count, and active-tool count appear
only when their owner provides a value. `context_bar.rs` formats compact token
values such as `8.5K / 1.0M`; hover can replace that with a usage percentage
bar. `turn_status.rs` formats timer plus token output (for example
`1m20s ⇣12k`) and queued-send hints. Unknown and zero values must retain the
source distinction rather than being fabricated in the renderer.

## 7. Pi-core mapping and Runie work plan

| Pi capability | Grok surface to reproduce | Runie deliverable |
|---|---|---|
| message lifecycle/streaming | user, assistant, thinking, markdown sections | actor snapshots + event/YAML/full-cell fixtures |
| tool lifecycle | specialized cards, partial output, terminal status | call-ID row identity and per-family projections |
| waiting/abort | typed status labels, spinner demand, cancellation | status actor and owned task cancellation |
| steering/follow-up | queued hints and send-now behavior | queue event sequences and viewport assertions |
| model/usage | context bar, timer, token/cost fields | optional metric snapshot with exact absent semantics |
| display state | grouping, fold, selection, sticky headers, scroll | pure layout/viewport reducer |
| themes/capabilities | semantic tokens, truecolor/quantization, glyph fallback | Opaline token projection + full-cell capture |

Implementation order:

1. Add a source path and Pi event mapping to every in-scope row above.
2. Add YAML sequences for each lifecycle/input/overlay/status branch; no sleeps.
3. Add deterministic animation-frame events and a four-geometry full-cell
   oracle (80×24, 100×30, 120×40, 160×48).
4. Compare Grok and Runie captures by glyph, width, foreground, background,
   modifiers, coordinates, and empty cells under the same capability profile.
5. Keep Grok-only surfaces documented as excluded until Pi promotes a matching
   core contract.

Current gaps remain explicit: full terminal-attribute capture, specialized
  card rendering/metrics, and complete actor-owned row identity across all
  live adapters. This audit is complete as a source inventory but the parity
  objective is not complete until those fixtures and implementations pass.
